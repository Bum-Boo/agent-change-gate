# Agent Change Gate

[English](../README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [中文](README.zh-CN.md)

[![CI](https://github.com/Bum-Boo/agent-change-gate/actions/workflows/ci.yml/badge.svg)](https://github.com/Bum-Boo/agent-change-gate/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](../LICENSE)

> このチャット経由で ACP が提案した編集はスコープを検査され、レビューするまで下書きのまま保持されます。

Agent Change Gate は、慎重なノート作業のためのデスクトップ ACP クライアントです。リクエスト時に、現在のノート本文、厳密な選択範囲、既存の YAML frontmatter のいずれかを選びます。プラグインはそのスコープを取得し、会話をノートとエージェントに結び付け、提案された置換をすべて下書きとして扱います。

下書きは、上限内で完全な行単位 diff として表示され、承認後にのみ適用されます。通常は正確な行 diff を使い、その計算が上限を超える場合は粗いものの完全な削除/追加表示に切り替えます。完全に描画できない大きな提案は適用できません。応答中にノートのパスまたは取得内容が変わると、古いテキストへの適用を拒否します。

> 状態: 手動テスト向け公開プレリリース（`0.2.0`）。GitHub Releases から取得できますが、Obsidian Community Plugins には未掲載です。コアヘルパー、転送上限、セッションのライフサイクル、状態保持には自動テストがあり、Hermes ACP の初期化も確認済みです。Obsidian GUI/モデルのワークフロー、外部ベータ、広範な互換性は未検証です。

## ゲートの対象

対象は Agent Change Gate で選択したコンテキストと、Agent Change Gate が行うノート書き込みです。

- 既定では、ホストプロンプトに含まれる現在のノート本文は選択した本文、選択範囲、frontmatter のみです。
- オプトインすると、同一の厳密なスコープ識別子（種類、範囲、内容）に関連する直近の表示済みユーザー/アシスタントメッセージを最大 12 件追加送信できます。
- 会話はエージェント起動 ID と Vault 相対ノートパスごとに分離され、実行ファイルやワークスペース変更時に以前の文脈を暗黙に転送しません。
- ACP クライアントのファイルシステム/ターミナル機能は付与せず、権限要求はフェイルクローズします。
- プラグインが適用するすべての変更に明示的な diff 承認が必要です。
- 古いノートパスまたは内容のスナップショットは拒否します。
- 上限内のレビュー diff を描画できる場合、ローカルチェックポイントから保護された Undo を 1 回行えます。
- スコープレシートはサイズ、決定的ハッシュ、結果を記録し、指示、ノート本文、モデル応答の平文は記録しません。

## ゲートの対象外

Agent Change Gate は ACP プロセスをサンドボックス化しません。Hermes などのエージェントは別のローカルプロセスとして動作し、独自のツール、ネットワーク、モデルプロバイダー、認証情報、メモリ、OS 権限を持つ場合があります。選択範囲外へアクセスできないこと、内容が端末内だけに留まること、他のプラグインが Vault を変更できないことは保証しません。

信頼できるエージェントを使用してください。実際のプロセス境界が必要なら、専用 OS アカウント、VM、またはコンテナを使ってください。

## 想定用途

- 同じノートとエージェントに戻る集中した会話
- 本文、選択範囲、frontmatter の書き込み前レビュー
- 無人の Vault 全体変更より慎重で元に戻せる編集を望む利用者
- 単一 ACP ランタイムに固定されず Hermes の第一級検出を使いたい利用者

## 想定しない用途

- 無人または一括 Vault 自動化
- このプラグイン経由の直接的なファイルシステム/ターミナル制御
- モデル、プロバイダーアカウント、エージェントソフトウェアの導入・設定
- モバイル利用
- OS サンドボックス

## 要件

- Obsidian デスクトップ 1.13.4 以降
- 設定済みプロファイルを持つ Hermes Agent、または明示設定した互換 ACP stdio エージェント
- モデル/プロバイダー認証情報はエージェント側で管理し、このプラグインへ貼り付けないこと

Windows ネイティブと WSL 転送をサポートします。Windows の Hermes 自動検出は WSL、次にネイティブ実行ファイルを試します。

## テスト用インストール

1. [0.2.0 GitHub プレリリース](https://github.com/Bum-Boo/agent-change-gate/releases/tag/0.2.0)から `agent-change-gate-0.2.0.zip` を取得します。
2. ライセンス通知を含むアーカイブ全体を次へ展開します。

   ```text
   <vault>/.obsidian/plugins/agent-change-gate/
   ```

   Obsidian は `main.js`、`manifest.json`、`styles.css` を読み込みます。`LICENSE`、`THIRD_PARTY_NOTICES.md`、`LICENSES/` も同じ場所に置いてください。

3. Obsidian の **設定 → コミュニティプラグイン**で再読み込みし、**Agent Change Gate**を有効化します。
4. **設定 → Agent Change Gate**で **Detect and check agents** を実行します。

## Hermes クイックスタート

[Hermes Agent](https://github.com/NousResearch/hermes-agent) が第一級の設定経路です。起動形式は次のとおりです。

```text
hermes -p <profile-id> acp
```

`hermes` が `PATH` にない WSL 環境では Linux 実行ファイルの絶対パスを指定します。プラグインは Hermes プロファイルをインストール、更新、書き換えしません。Hermes は利用者が導入する外部ソフトウェアであり、本プロジェクトには同梱・保守されません。

## その他の ACP エージェント

設定では、安定したローカルラベル、ネイティブ/WSL 転送、実行コマンド、1 行 1 個のリテラル引数、明示的 ACP 作業ディレクトリを持つ argv 専用プロファイルを登録できます。

コマンドは `shell: false` で直接起動します。カスタム環境変数欄は意図的にありません。引数は Obsidian のプラグインデータへ保存されるため、トークン、API キー、パスワードを入れず、エージェント自身の安全な仕組みで設定してください。

設定可能であることは普遍的互換性を意味しません。正確な検証版は [互換性文書](COMPATIBILITY.md)を参照してください。

## 使い方

1. Markdown ノートを開きます。
2. 盾付きチャットアイコンから Agent Change Gate を開きます。
3. エージェント、**Ask** または **Suggest an edit**、スコープを選びます。
4. 送信します。Enter は送信、Shift+Enter は改行で、IME 変換中は送信しません。
5. **Stop** はローカル待機を止め ACP キャンセルを要求します。子プロセスが無視しても、そのターンの提案は適用されません。
6. 編集では追加/削除行を確認し、**Apply this edit** または **Discard** を選びます。
7. **Scope receipts** で、指示・ノート本文・モデル応答の平文を除いたローカル結果ログを確認します。

## スコープ規則

- **Note body** は既存 YAML frontmatter を除外します。
- **Current selection** は送信時に取得した空でない選択が必要です。
- **YAML frontmatter** は既存の完全なブロックが必要で、解析可能な YAML を含む完全な置換ブロックのみ受け付けます。

承認後でも、アクティブなノートパスまたは内容が取得時のスナップショットと一致しなければ拒否します。

## プライバシーとローカルデータ

プラグイン自身は HTTP 要求を行わず、テレメトリもありません。各 ACP ターンには指示、Vault 相対の論理ノートパス、選択スコープ、タスク/スコープラベルが入ります。厳密スコープのスレッド文脈を選んだ場合のみ、直近の表示済みユーザー/アシスタントメッセージを最大 12 件、各 4,000 文字まで追加します。エージェントはこれをモデルプロバイダーへ送り、費用が発生する場合があります。

ローカルデータは暗号化されない平文で、制限付きチャット履歴、対象となるノート全体の前後復旧チェックポイント、秘密を含めてはならない起動設定、最大 500 件・90 日保持のスコープレシートを含み得ます。同期やバックアップが端末外へコピーする場合があります。全体で最大 200 スレッド、2,000,000 メッセージ文字を保持し、チェックポイントにもサイズ、件数、期間、総量の上限があるため、大きなノートには作成されない場合があります。レシートに指示、ノート、モデル応答はありませんが、決定的ハッシュは推測内容の照合に使えます。チャット、チェックポイント、レシートは個別に消去できます。機密ノートには [PRIVACY.md](../PRIVACY.md) を先にお読みください。

## セキュリティモデル

ホスト側には、サイズ制限付きスキーマ検証応答、上限付き diff、非アクティブな平文表示、厳密な古いスナップショット検査、書き込み前 diff、シェル展開なし、制限された子環境、空の ACP クライアント能力、クライアント側ファイルシステム/ターミナルメソッド拒否、フェイルクローズ権限処理があります。第一級 Hermes 起動では MCP 抑止フラグを設定し、空のセッション MCP リストを送ります。別プロセスはホスト要求を無視できます。

これらはホスト経由の偶発的アクセスを減らしますが、子プロセスの OS サンドボックスではありません。[SECURITY.md](../SECURITY.md) を参照してください。一般的な不具合は [GitHub Issues](https://github.com/Bum-Boo/agent-change-gate/issues)へ。機密の Vault 内容や脆弱性詳細を公開 Issue に載せず、セキュリティ文書の手順に従ってください。

## 開発

```bash
npm ci
npm run check
```

隔離したテスト Vault にのみデプロイします。

```powershell
$env:OBSIDIAN_LAB_VAULT='C:\absolute\path\to\lab-vault'
npm run deploy:lab
```

Vault ルートの `.agent-change-gate-lab` が正確に `agent-change-gate isolated test vault` を含む場合にだけコピーします。テスト Vault に意図して作成し、個人用・本番 Vault へは追加しないでください。
