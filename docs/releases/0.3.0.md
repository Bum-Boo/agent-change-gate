# Agent Change Gate 0.3.0 (unreleased)

This document describes development work planned for the next public prerelease. Version `0.3.0` has not been published, has no downloadable release asset, and is not listed in Obsidian Community Plugins. The latest downloadable build remains `0.2.0`.

## Planned highlight: experimental Vault Batch Review

- Opt in explicitly before batch controls are available.
- Select a bounded set of Markdown notes rather than granting open-ended vault access.
- Limit one batch to at most 20 files and 500,000 selected-scope characters.
- Start one fresh ACP turn per note, sequentially, without thread history or other selected-note contents in that host prompt.
- Keep every returned replacement as a draft until its own bounded diff is reviewed.
- Require a final confirmation for the approved write set.
- Recheck every approved path and exact captured content before the first write; one stale target blocks the batch before writing begins.
- Require every selected target to be closed in Obsidian before scan, apply, or recovery so a disk write cannot race an editor buffer.
- Exclude unattended writes, approve-all, file creation, deletion, moves, renames, and non-Markdown changes.

## Recovery boundary

Multi-file writes are not a filesystem transaction. A later write can fail after earlier files succeeded. The batch result must report each file separately, and guarded best-effort rollback may restore only a file that still exactly matches the plugin-recorded post-edit content. It must never overwrite a file changed after the batch.

Closing Obsidian or losing the agent during a run must not trigger automatic resume, rollback, or additional billed turns. An interrupted run is reconciled against its recorded before/after state and returned to the user for a decision.

## Privacy and provider impact

The batch instruction, vault-relative logical path, and selected scope of each note are sent to the configured ACP agent in separate turns. The host supplies no conversation history in batch mode, but the agent process or provider may retain or correlate turns and may charge for each one. The bounded local recovery journal stores the original replaced-scope plaintext, paths, ranges, hashes, and per-file state, but not full-note copies or replacement text. It is unencrypted plugin data and may be copied by vault synchronization or backup software.

## Verification still required

- complete automated host integration tests for sequential turns, cancellation, all-target stale blocking, partial apply, interrupted-run reconciliation, and guarded rollback;
- a manual Obsidian GUI matrix for selection, context/cost preflight, per-draft review, final confirmation, failure states, and recovery;
- a real-model batch run against the exact supported Hermes version;
- at least one batch run against another ACP implementation;
- packaged-build checks for recovery-state retention and deletion;
- downloaded prerelease asset and checksum verification after publication.

Until those checks are complete, public copy must call Vault Batch Review experimental and must not describe it as unattended automation, atomic, transaction-safe, fully recoverable, released, or Community Plugins-distributed.
